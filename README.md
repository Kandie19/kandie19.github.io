## AEGIS: Public by Design, Proprietary by Default

AEGIS is one of the central engineering projects represented in this portfolio.

The portfolio deliberately follows a **need-to-know disclosure model**.

Publicly presented information focuses on:

- Product purpose
- High-level capabilities
- Security and intelligence themes
- Engineering principles
- Simulated demonstrations
- Public-facing architecture concepts
- The problem being solved

It intentionally does **not** publish:

- Source code
- Private IP
- Production credentials or secrets
- Private infrastructure details
- Sensitive deployment information
- Internal security controls
- Proprietary algorithms or implementation details
- Operational data that should remain private

The engineering story is therefore visible without turning the portfolio into an accidental technical disclosure.

## Engineering Philosophy

The portfolio reflects several principles that guide my work:

### Architecture First

Systems should be designed with their future operating environment in mind — not merely made to work for the first release.

### Security by Design

Security is part of the system from the beginning, not a cosmetic layer added after functionality is complete.

### Intelligence Over Information

Data becomes valuable when a system can transform it into useful context, decisions, and action.

### Build for Operations

A system is not finished when the code runs. Reliability, observability, maintainability, resilience, and operational clarity matter.

### Demonstrate, Don't Expose

Technical capability can be demonstrated through controlled interfaces, simulations, and high-level architecture without publishing protected implementation details.

### Impact Over Complexity

Technology is valuable when it solves a meaningful problem. Complexity is not a substitute for outcomes.

## Why Static?

The portfolio does not need a complex application backend to communicate its primary purpose.

A static architecture provides:

- Fast page delivery
- Low operational overhead
- Minimal attack surface
- Straightforward deployment
- High portability
- Easy version control
- Clear separation between public presentation and private product infrastructure

Interactive demonstrations can still be introduced through client-side JavaScript and controlled simulations without turning the portfolio itself into a gateway to private systems.

## Local Development

Because this is a static site, no backend service is required to preview the core portfolio.

### Option 1 — Open directly

Open `index.html` in a modern browser.

### Option 2 — Use a local static server

From the repository root:

```bash
python -m http.server 8000
```

Then open:

```text
http://localhost:8000
```

A local server is recommended when testing navigation, asset paths, caching behaviour, or browser security restrictions.

## Engineering Standards

Changes to this repository should preserve several non-negotiables:

1. **Do not expose private credentials, secrets, IP, or production infrastructure.**
2. **Do not publish proprietary AEGIS implementation details.**
3. **Keep the portfolio accessible and understandable to technical and non-technical decision-makers.**
4. **Preserve responsive behaviour across desktop, tablet, and mobile layouts.**
5. **Avoid visual changes that introduce clipping, truncation, overlap, or unreadable content.**
6. **Keep navigation functional and ensure every public section has a clear purpose.**
7. **Treat the personal brand and product brands as distinct identities.**
8. **Prefer maintainable, explicit front-end code over unnecessary complexity.**
9. **Validate important visual changes before deployment.**
10. **Protect the boundary between public demonstration and private engineering infrastructure.**
